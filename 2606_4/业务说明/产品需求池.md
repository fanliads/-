# 【产品需求池】业务说明

## 目标

产品需求池沿用原始需求池已经确认的 Linear 风格与列表交互，作为产品经理持续推进需求的主工作台。页面重点不是重新包装一套系统，而是让产品需求从拆分、排期、设计、开发、上线到回归评估的状态和责任关系可以在同一张高密度列表中快速维护。

本需求只定义 UE 优化迭代的业务与原型要求，不直接修改生产前端、后端接口或数据结构。

## 交互说明

### 列表

1、页面结构与原始需求池保持一致：
* 左侧为安静导航，当前项高亮“产品需求”。
* 顶部为单行工具栏，包含搜索、筛选、展示设置和新建产品需求。
* 使用视图切片切换“全部产品需求”“未排期”“待设计”“开发中”“本迭代”“空状态”。
* 不再使用汇总卡片条，不需要“操作”列。

2、peek 操作与原始需求池保持一致：
* 在列表中 hover 到具体数据条目时，敲击空格键打开 peek 窗口。
* 长按空格键则保持 peek 窗口一直在前台展示。
* 键盘上下切换或鼠标滚动时，peek 内容跟随当前 hover 的数据更新。
* 再次敲击空格键关闭 peek。

3、点击列表数据条目后进入产品需求详情页面。详情页需要展示产品需求所有相关业务要素，包括基础字段、父原始需求、排期、交付材料、价值评估和历史活动。

4、列表中所有展示字段，除了“产品需求标题”和“产品需求编号”以外，支持直接编辑。鼠标 hover 时需要有可编辑状态，点击单元格打开 Linear 风格浮层菜单：
* 状态字段：待设计、设计中、开发中、测试中、已上线、已验收、验收不通过、作废。状态设置为“作废”或“验收不通过”时，需要输入备注原因。
* 迭代字段：支持选择已有迭代，也支持清空为“未排期”。
* 负责人、处理人字段：使用纯文本菜单，不展示头像点。
* 期望上线时间、实际上线时间：使用日期选择器，不使用普通下拉菜单。
* 工作量、价值评分：允许在单元格内快速维护，工作量可用文本或预设值，价值评分建议 1-5 分。

5、产品需求标题列承载主要识别信息：
* 展示产品需求编号、标题、需求类型、直接创建标识。
* 若来自原始需求，提供父原始需求入口；入口使用扁平图标或文本链接，点击时不进入产品需求详情。
* PRD 地址、设计文档地址在列表中以图标展示，hover 给提示，点击打开对应链接或原型占位。

### peek

1、peek 弹出后展示产品需求完整摘要：
* 产品需求编号、标题、状态、优先级、需求类型。
* 所有列表字段。
* 父原始需求摘要：原始需求编号、标题、业务提交摘要、业务判定摘要。
* 交付材料：PRD 地址、设计文档地址。
* 排期信息：迭代、期望上线时间、实际上线时间。
* 历史活动记录。

2、peek 底部只保留“详情”按钮，点击后进入完整产品需求详情页。

### 详情

详情页直接展开产品需求所有关联业务板块，避免抽屉里堆叠小卡片：

1、主档字段：
* 产品需求编号、标题、状态、优先级、业务线、功能模块、需求类型。
* 负责人、处理人、创建人。
* 迭代、工作量、价值评分、期望上线时间、实际上线时间。

2、需求描述：
* 展示产品需求描述正文。
* 支持编辑描述。

3、父原始需求：
* 如果产品需求来自原始需求拆分，需要展示父原始需求编号、标题、业务提交、业务判定、外部需求单入口。
* 如果产品需求为直接创建，展示“直接创建”来源说明。

4、交付材料：
* PRD 地址、设计文档地址支持直接维护。
* 链接图标需要有 hover 提示。

5、迭代与排期：
* 支持将产品需求纳入迭代、移出迭代、切换迭代。
* 未排期状态必须在列表和详情中明显可见，但不使用强烈告警色。

6、价值回归：
* 支持维护价值评分。
* 支持记录上线后回归备注，原型阶段只验证信息结构。

### 新建产品需求

1、从产品需求池直接新建产品需求时，弹层字段至少包含：
* 产品需求标题
* 业务线
* 优先级
* 需求类型
* 负责人或处理人
* 迭代，可为空
* 期望上线时间
* 需求描述

2、直接创建的产品需求需要在列表和详情中展示“直接创建”标识。

### 样式

1、整体视觉、密度、hover 状态、浮层菜单、日期选择器、peek 行为与当前原始需求池原型保持一致。

2、所有表头、按钮、浮层、空状态文案必须使用中文。

3、PRD、设计文档、父原始需求、直接创建等辅助信息使用扁平图标或轻量文本，不使用重彩色标签堆叠。

4、长标题不能撑破列表列宽；在 1435x931 视口下，列表、peek、详情页不能发生非预期重叠。
