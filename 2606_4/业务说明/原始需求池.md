# 【原始需求池】业务说明

## 交互说明
### 列表
1、peek操作
* 在列表中时，用户操作在hover到具体数据条目时，在键盘上敲击“空格键”，peek窗口弹出
* 长按“空格键”则保持peek窗口一直在前台展示。
* 键盘“上下切换”或鼠标滚动时，peek窗口的内容根据当前hover的数据展示对应内容。再次敲击“空格键”取消peek弹窗

2、在列表页面，鼠标点击数据条目后进入到详情页面。详情页面展示原始需求所有相关的业务要素，具体排版待定

3、列表中所有展示的字段，除了“需求标题”、“需求编号”以外的字段，支持直接编辑。鼠标hover时有状态（强烈建议参考linear的交互细节）
* 状态字段：待评估、待设计、已设计、开发中、已上线、验收不通过、拒绝，状态设置为“拒绝”时，需要输入备注原因
* 不需要“操作”列了
* update改为中文的“创建时间”
* 增加“期望上线时间”

4、列表中增加一个“需求单”链接的字段，目前是一个超链接的跳转按钮，后期考虑是直接做成系统内置页面。兼容两种模式

### peek
1、peek弹出后展示所有信息。包括所有列表字段、业务提交（含业务判定）的字段以及历史活动记录的信息

2、提供“详情”按钮，点击按钮后，peek打开成一个页面

### 详情
详情页面直接展开原始需求所有关联的业务板块和业务字段，合理考虑页面布局

1、详情页需要提供“需求拆分”功能
* 在详情页中展示该原始需求已拆分出的产品需求列表
* 支持新增产品需求拆分项
* 支持基于原始需求生成建议拆分项
* 支持直接编辑拆分项的标题、产品经理、优先级、状态
* 支持删除拆分项
* 原型阶段只验证交互与信息结构，不引入后端 API 改动

### 样式
1、“加急”、“外部提交”改为icon（扁平），hover给提示

2、注意所有表头不要以英文进行标记，用中文
