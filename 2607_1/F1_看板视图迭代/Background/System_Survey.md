# F1 看板视图迭代—现有系统调研

> 调研状态：已确认（2026-07-20）
> 调研依据：2026-07-18 用户访谈与已确认需求背景。

## 1. Original System Core Logic

- 系统当前同时管理原始需求和产品需求，两类需求具有各自的字段及状态集合。
- 当前看板能够在原始需求与产品需求对象之间切换，并按状态呈现需求。
- 用户期望通过拖拽改变需求状态；本期确认各状态之间允许任意互转，不增加强制流转顺序。
- 用户点击需求后需要查看完整信息，但不接受在看板右侧展开常驻详情/判断栏的结构。
- 系统已有角色权限继续决定页面访问与操作能力，本期不调整权限定义。

## 2. Impacted Existing Pages

| 页面 | 影响类型 | 本期变化 |
|---|---|---|
| 看板视图 | 现有页面改造 | 改为全宽主工作区，保留原始需求/产品需求切换，移除右侧常驻信息栏结构 |
| 原始需求详情 | 既有页面复用 | 由原始需求卡片跳转进入，详情能力本期不重做 |
| 产品需求详情 | 既有页面复用 | 由产品需求卡片跳转进入，详情能力本期不重做 |
| 迭代详情 | 既有入口联动 | 可进入带迭代上下文的产品需求看板，具体入口在 F2 中设计 |

## 3. Constraints & Dependencies

### 已确认约束

- 看板必须同时支持原始需求与产品需求。
- 两类需求不得混成同一套状态列，应分别使用自身状态集合。
- 状态允许任意互转，但操作仍受现有权限控制。
- 页面必须保持全宽；选中卡片前后看板宽度不变。
- 不使用右侧常驻详情、辅助判断或信息汇总栏。
- 角色、权限及完整需求详情不在本期改造范围。

### 依赖

- 依赖现有原始需求、产品需求列表与状态更新能力。
- 依赖现有原始需求详情页和产品需求详情页。
- 依赖 F2 提供迭代入口及迭代上下文。

### 当前设计假设

- 默认按状态分组；是否增加其他分组方式留待概念方案比较。
- 返回看板时应恢复对象类型、筛选条件与滚动位置。

## 4. Interview Decisions

| 问题 | 结论 |
|---|---|
| 看板对象范围 | 支持原始需求与产品需求 |
| 状态流转 | 允许任意状态互转 |
| 页面结构 | 全宽看板，无右侧常驻详情栏 |
| 权限 | 沿用现状，本期不调整 |
