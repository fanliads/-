# F1 看板视图迭代—需求背景

> 状态：待确认

## 1. 需求概述

现有产品需求池已经具备状态、优先级、处理人和所属迭代等执行字段，但列表视图不适合持续观察各阶段工作分布。需要新增以状态流转为核心的看板视图，让团队在同一工作面中识别阻塞、调整负责人并推进需求。

### 1.1 目标用户

- 核心用户：产品经理、产品负责人。
- 协同用户：项目经理及具备看板访问权限的业务角色。

### 1.2 核心价值

- 用列分组直观呈现工作状态与在制需求。
- 减少在列表、详情和编辑弹窗间切换的成本。
- 让看板与产品需求池、迭代管理共享同一数据与权限口径。

## 2. 初步需求假设

- 看板同时支持原始需求与产品需求，通过同一页面顶部的对象类型切换进入各自看板。
- 两类需求分别使用自身的状态集合与卡片字段，不混在同一列组中展示。
- 默认按需求状态分列，优先级、负责人、迭代作为筛选条件。
- 用户可在权限范围内拖拽卡片改变状态，各状态之间允许任意互转；失败时卡片回滚并说明原因。
- 看板始终保持全宽，不出现挤占看板空间的右侧常驻详情/辅助判断栏。
- 点击卡片进入对应的原始需求或产品需求独立详情页，不在看板内复制一套详情模型。
- 快速改负责人、优先级等轻量操作可在卡片菜单或居中弹窗完成，不使用右侧分栏。
- 从某个迭代进入看板时，自动锁定该迭代筛选条件。

## 3. Core Scenarios

### 3.1 查看当前迭代执行情况

1. 用户进入看板并选择原始需求或产品需求视图。
2. 系统按当前对象的状态分列；从迭代详情进入时，对支持迭代归属的对象应用迭代筛选。
3. 用户观察各列数量、优先级和负责人分布。
4. 用户通过筛选快速定位本人负责或高优先级需求。

### 3.2 推进需求状态

1. 用户将卡片拖到目标状态列。
2. 系统校验权限和状态流转规则。
3. 校验通过后保存状态并更新列数量。
4. 保存失败时卡片回到原列，并显示可理解的失败原因。

### 3.3 查看并补充需求信息

1. 用户点击看板卡片。
2. 系统根据卡片类型进入对应的原始需求或产品需求独立详情页，不压缩或分割看板工作区。
3. 用户查看或编辑负责人、优先级和迭代等字段。
4. 返回看板后，系统恢复此前的迭代、筛选和滚动位置，并同步最新字段。

## 4. 范围边界

### 本期包含

- 全宽看板、分列、卡片、筛选、拖拽流转、独立详情页跳转、上下文恢复及必要状态反馈。

### 本期暂不包含

- 自定义工作流编辑器、跨项目聚合看板、复杂报表与实时多人光标。
- 右侧常驻详情栏、右侧辅助判断栏及任何持续压缩看板宽度的选中态分栏。

## 5. 待确认问题

- 是否需要首版支持按负责人或优先级切换分组？
- 卡片是否需要显示工作量点数与截止日期？

## 6. 页面结构验收约束

- 未选中和选中卡片时，看板主区域宽度保持一致。
- 页面右侧不得出现截图红框形式的常驻信息栏。
- 查看完整需求信息必须进入独立详情页；返回后保留看板上下文。
- 快捷编辑若使用弹窗，弹窗关闭后回到原看板，不改变列布局。
