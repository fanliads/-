# F1 看板视图迭代—业务流程

## 1. 流程逻辑

用户进入统一看板后选择需求对象，系统按该对象的状态集合组织卡片。用户可以通过筛选聚焦范围，也可以将有权限编辑的卡片拖至任意状态。完整信息始终进入独立详情页，返回时恢复工作上下文。

## 2. 查看、流转与详情闭环

```mermaid
flowchart LR
    subgraph U["看板用户"]
        U1["进入看板"]
        U2["选择原始需求或产品需求"]
        U3["搜索或筛选"]
        U4["拖拽卡片到目标状态"]
        U5["点击卡片查看详情"]
        U6["返回看板"]
    end

    subgraph K["看板业务"]
        K1["加载对象对应的状态列和卡片"]
        K2["计算筛选结果与列数量"]
        K3{"具备状态编辑权限？"}
        K4["提交任意目标状态"]
        K5{"保存成功？"}
        K6["更新卡片位置与列数量"]
        K7["回滚卡片并提示原因"]
        K8["记录对象类型、筛选与滚动位置"]
        K9["恢复上下文并同步卡片"]
    end

    subgraph D["既有需求详情"]
        D1["打开对应独立详情页"]
        D2["查看或编辑完整信息"]
    end

    U1 --> U2 --> K1
    K1 --> U3 --> K2
    K2 --> U4 --> K3
    K3 -->|是| K4 --> K5
    K3 -->|否| K7
    K5 -->|是| K6
    K5 -->|否| K7
    K2 --> U5 --> K8 --> D1 --> D2 --> U6 --> K9
```

## 3. 状态变化规则

- 原始需求和产品需求分别使用现有状态集合。
- 任意现有状态均可转到任意其他现有状态。
- 本期不新增审批节点或强制前后置状态。
- 权限不足、记录已删除或保存失败时，需求状态保持原值。
