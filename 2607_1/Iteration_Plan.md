# 2607_1 产品迭代任务与计划

## 1. 迭代目标

让产品经理能够完成“创建迭代 → 需求排期 → 看板执行 → 进度跟踪 → 迭代收尾”的闭环，同时延续 `2606_4` 已确认的 Linear 风格、信息密度和权限规则。

## 2. 范围与任务

### F1 看板视图迭代

- 明确看板的目标用户、默认入口与默认分组方式。
- 支持在原始需求与产品需求两类看板之间切换，两类对象分别使用自身状态集合。
- 设计按状态分组的主看板，以及必要的筛选、排序与视图记忆能力。
- 定义卡片最小信息集：编号、标题、优先级、负责人、所属迭代等。
- 支持权限范围内拖拽卡片变更状态，并提供成功反馈、失败回滚和审计线索。
- 状态之间允许任意互转，本期不新增强制状态机或前后置校验。
- 看板保持全宽展示；不设置挤占看板宽度的右侧常驻详情/辅助判断栏。
- 点击卡片进入独立详情页；无需离开看板即可完成的轻量操作，使用卡片内操作或非分栏式弹窗。
- 定义空列、空结果、加载、异常和无权限状态。

### F2 迭代管理优化

- 明确迭代对象模型、状态和关键日期。
- 保持当前迭代管理页面结构、字段与操作入口不变。
- 修复迭代周期只能选择“单周/双周”的限制：周期以开始日期和结束日期为准，单周/双周降级为快捷预设。
- 支持临时迭代按任意日期区间创建，不要求周期为整周或 7 天的整数倍。
- 支持创建、编辑、启动、完成与归档迭代。
- 支持未排期需求查看、批量排期、移出迭代和跨迭代调整。
- 提供迭代需求分布、完成进度和基础容量提示。
- 支持从迭代进入对应看板，并保持筛选上下文。
- 迭代列表与迭代详情均采用单一主内容区，不附加右侧常驻判断面板。
- 角色与权限沿用现有配置，本期不调整权限模型。
- 定义进行中迭代变更、已完成迭代只读和权限控制规则。

## 4. 建议验收主线

1. 产品经理创建一个迭代并配置周期。
2. 从未排期需求中选择产品需求加入迭代。
3. 进入该迭代看板，按状态查看任务。
4. 拖拽需求推进状态，并进入独立详情页核对信息。
5. 查看进度与剩余工作，完成并归档迭代。

## 5. 已确认决策

- 看板同时支持原始需求和产品需求。
- 原始需求与产品需求均允许在自身状态之间任意互转。
- 迭代管理保留当前页面结构，仅调整周期能力及既定管理闭环。
- 权限模型不在本期调整。

## 6. 待确认决策

- 看板首版是否只按状态分组，还是同步支持按负责人、优先级分组。
- 容量采用需求数量、工作量点数，还是两者并存。
- 是否允许同时存在多个“进行中”迭代。
- 迭代完成时，未完成需求的迁移规则。
- 临时迭代是否需要独立的“临时迭代”类型标识，还是仅通过自定义日期区间表达。

## 7. 跨需求页面结构约束

- F1 看板与 F2 迭代管理都使用全宽主工作区。
- 禁止出现截图红框所示的右侧常驻详情、判断或信息汇总栏。
- 禁止因选中卡片或列表项而持续压缩主看板、列表或规划区宽度。
- 完整对象信息放在独立详情页；创建、排期、迁移等聚焦型操作可使用居中弹窗。
- 页面级筛选和批量操作放在主内容区顶部，不另建第二信息侧栏。
