# F2 迭代管理优化—页面结构

## 1. 页面层级

| 页面 | 类型 | 说明 |
|---|---|---|
| 迭代列表 | 保持现有结构 | 继续作为迭代管理入口 |
| 新建/编辑迭代 | 局部修改 | 周期区改为“预设 + 可编辑起止日期 + 天数” |
| 迭代详情 | 保持现有结构 | 展示真实周期并联动看板 |
| 产品需求看板 | 跨需求复用 | 接收迭代筛选上下文 |

## 2. 迭代列表

### 保持不变

- 页面标题、主列表结构、现有筛选和操作入口。
- 现有迭代字段与权限可见性。
- 标题区后直接进入搜索、筛选和列表，不设置“进行中 / 待启动 / 本季度已完成”等大尺寸数量摘要卡。

### 信息取舍

- 迭代状态已在列表行和状态筛选中表达，不重复占用首屏空间。
- 本期不定义季度统计口径，因此不展示“本季度已完成”等弱关联指标。
- 若未来需要进度洞察，应基于明确决策场景单独设计，例如临近结束但未完成需求过多，而不是只展示静态数量。

### 周期展示调整

- 日期区间：`YYYY-MM-DD ～ YYYY-MM-DD`。
- 辅助信息：`N 天`。
- 若现有页面展示“单周/双周”，可在符合 7/14 天时作为弱辅助文案，不替代真实日期。
- 点击记录进入独立迭代详情，不在右侧展开详情栏。

## 3. 新建/编辑迭代弹窗

### 3.1 原有字段

- 名称、团队、目标、状态及其他现有字段保持原顺序和规则。
- 现有必填标记与权限保持不变。

### 3.2 周期设置区

- 快捷预设：[单周] [双周]。
- 开始日期：必填，日期选择器。
- 结束日期：必填，日期选择器。
- 计算结果：`周期 N 天`。
- 自定义提示：用户修改预设结果后显示“自定义周期”。

### 3.3 预设规则

- 先有开始日期再选择单周：结束日期 = 开始日期 + 6 天。
- 先有开始日期再选择双周：结束日期 = 开始日期 + 13 天。
- 若先选择预设但未填开始日期，引导用户先选择开始日期，不写入错误日期。
- 修改起止任一日期后立即重算天数。

### 3.4 校验与按钮

- 错误：结束日期不得早于开始日期。
- 错误展示在日期区附近，不使用全局模糊提示替代。
- 主按钮：[创建迭代] 或 [保存]。
- 次按钮：[取消]。
- 日期非法或原有必填项缺失时主按钮不可提交。

## 4. 迭代详情

- 保持当前结构和字段组织。
- 周期位置展示真实起止日期与天数。
- 操作入口沿用现有权限。
- “查看看板”进入 F1 产品需求看板并自动应用当前迭代筛选。
- 不增加右侧常驻详情或判断面板。

## 5. 历史数据展示

- 读取已有开始、结束日期。
- 展示时重新计算自然日天数。
- 历史周期枚举不覆盖真实日期。
- 缺失或非法历史日期按现有异常治理方式提示，不在前端静默猜测。

## 6. 响应与反馈

- 预设带出日期：即时更新。
- 日期修改：即时重算。
- 保存中：禁用重复提交并显示局部加载。
- 保存成功：关闭弹窗并刷新对应记录。
- 保存失败：保留输入并显示可理解错误。

## 7. 明确禁止

- 仅提供单周/双周且不可修改日期。
- 强制以 7 天整数倍作为合法性条件。
- 为临时周期强制新增“临时迭代”类型。
- 选中迭代后在右侧展开常驻详情栏。
- 在列表顶部堆叠不支持具体决策的状态数量摘要卡。
