# F2 迭代管理优化—现有系统调研

> 调研状态：已确认（2026-07-20）
> 调研依据：2026-07-18 用户访谈与已确认需求背景。

## 1. Original System Core Logic

- 系统已有迭代管理页面及固定的页面结构、字段和操作入口。
- 当前创建迭代时只能按“单周”或“双周”设置周期，无法表达非整周的临时迭代。
- 迭代与产品需求存在归属关系，可作为需求排期及看板筛选依据。
- 现有角色权限已经覆盖迭代相关访问和操作，本期不修改权限模型。

## 2. Impacted Existing Pages

| 页面 | 影响类型 | 本期变化 |
|---|---|---|
| 迭代管理 | 现有页面局部改造 | 保持当前结构，放开周期限制并支持任意起止日期 |
| 新建/编辑迭代 | 现有交互改造 | 单周/双周改为快捷预设，增加自定义开始与结束日期 |
| 迭代详情 | 现有页面复用与补充 | 保持现有结构，不增加右侧常驻详情栏 |
| 产品需求池 | 既有能力联动 | 继续展示和编辑所属迭代，本期不重做需求池结构 |
| 看板视图 | 跨需求联动 | 从迭代进入时携带对应迭代上下文 |

## 3. Constraints & Dependencies

### 已确认约束

- 当前迭代管理页面结构保持不变。
- 迭代真实周期由开始日期与结束日期决定，不再受整周枚举限制。
- 单周/双周仅作为快捷预设保留。
- 支持不足 7 天、超过 14 天及跨非整周日期的临时迭代。
- 现有权限不在本期调整。
- 不引入右侧常驻详情/辅助判断栏。

### 依赖

- 依赖现有迭代数据、产品需求所属迭代关系和权限校验。
- 依赖现有创建/编辑迭代接口能够保存真实起止日期；若接口仍以周期枚举为必填，需要在实施阶段兼容调整。
- 依赖 F1 看板接收迭代上下文并按所属迭代筛选产品需求。

### 当前设计假设

- 历史数据已有合法起止日期，并以这些日期作为兼容与展示依据。
- 是否显式标记“临时迭代”将在概念方案中比较，当前不视为必填类型。

## 4. Interview Decisions

| 问题 | 结论 |
|---|---|
| 页面结构 | 保持当前结构不变 |
| 周期能力 | 支持任意合法起止日期 |
| 权限 | 沿用现状，本期不调整 |
| 看板联动 | 迭代作为产品需求看板筛选上下文 |
