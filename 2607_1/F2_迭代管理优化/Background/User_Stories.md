# F2 迭代管理优化—用户故事

## US-F2-01 使用周期预设创建迭代

**作为** 产品经理，  
**我希望** 继续使用单周或双周快捷方式创建常规迭代，  
**以便于** 保持原有操作效率。

### 验收标准

1. 新建表单保留“单周 / 双周”快捷预设。
2. 选择预设后，根据开始日期自动带出连续 7 天或 14 天的结束日期。
3. 表单同时展示可编辑的开始日期、结束日期和计算后的周期天数。
4. 保存仍遵守现有必填字段和权限规则。

## US-F2-02 创建非整周临时迭代

**作为** 产品经理，  
**我希望** 使用任意开始和结束日期创建迭代，  
**以便于** 安排临时修复、专项交付或非整周工作。

### 验收标准

1. 用户可以直接输入或选择任意合法起止日期。
2. 支持不足 7 天、超过 14 天及跨非整周日期。
3. 起止日期均计入周期，同日开始结束显示 1 天。
4. 手动修改预设日期后显示“自定义 · N 天”。
5. 不要求额外选择“临时迭代”类型。

## US-F2-03 校验非法日期

**作为** 创建或编辑迭代的用户，  
**我希望** 系统即时提示非法周期，  
**以便于** 在保存前纠正日期。

### 验收标准

1. 结束日期早于开始日期时，日期字段附近显示明确错误。
2. 存在日期错误时禁止保存。
3. 修改任一日期后立即重新计算天数并清除已解决的错误。
4. 日期错误不清空名称、目标等其他已填内容。

## US-F2-04 编辑已有迭代周期

**作为** 有编辑权限的产品经理，  
**我希望** 修改已有迭代的起止日期，  
**以便于** 应对计划变化。

### 验收标准

1. 编辑表单展示真实起止日期和计算天数。
2. 历史周期枚举不限制日期编辑。
3. 保存后列表、详情、需求选择器和看板上下文同步显示新日期。
4. 现有迭代状态和权限限制继续生效，本期不改变。

## US-F2-05 兼容历史迭代

**作为** 迭代查看者，  
**我希望** 历史单周/双周迭代继续正常展示，  
**以便于** 无需人工修订已有数据。

### 验收标准

1. 历史迭代以已有开始日期和结束日期展示。
2. 系统按真实日期重新计算展示天数。
3. 历史记录无需批量迁移或人工重存。
4. 若历史枚举与日期不一致，展示和计算以日期为准。

## US-F2-06 从迭代进入看板

**作为** 产品经理，  
**我希望** 从迭代进入对应产品需求看板，  
**以便于** 跟踪该迭代内需求的执行状态。

### 验收标准

1. 迭代页面保留或提供“查看看板”入口。
2. 进入后自动切换产品需求看板并应用当前迭代筛选。
3. 看板显示真实迭代名称和日期上下文。
4. 返回后恢复原迭代页面状态。

## US-F2-07 保持现有结构与权限

**作为** 现有系统用户，  
**我希望** 周期能力升级后页面结构和权限不发生意外变化，  
**以便于** 继续按熟悉的方式管理迭代。

### 验收标准

1. 迭代列表、详情及现有字段保持原结构。
2. 创建、编辑、启动、完成等权限沿用现有规则。
3. 不新增右侧常驻详情/辅助判断栏。
4. 本期不新增审批流程或角色。
